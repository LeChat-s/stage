# Stage Combat Update v0.37.0

Основа: рабочая ревизия `stage_combat_update_v0363`.

## Главное

### Чумной Доктор — первый полноценный второй билд

Добавлен `res://src/data/builds/definitions/doctor.tres` и пакет карт:

- `Заражённый надрез` — прямой урон, 2 стака Яда, +1 Вирулентность;
- `Споры чумы` — Яд всем врагам и Вирулентность за заражённые цели;
- `Посев культуры` — добавляет и продлевает Яд;
- `Фильтрующая маска` — блок + очистка дебаффов;
- `Вскрытие` — payoff: дополнительный урон за каждый стак Яда и расход Яда.

Способности:

1. **Смертельное облако** — массовый Яд, КД 3.
2. **Полевой антидот** — блок + очистка дебаффов, КД 2.
3. **Катализатор** — за 3 Вирулентности немедленно активирует Яд на всех врагах и не завершает ход.

В репозитории пока нет отдельного sprite sheet формы Доктора, поэтому билд временно использует базовый `Д13list.png`. Его можно заменить во вкладке «Внешность» конструктора без изменения кода.

## Универсальный ресурс билда

`ContaminationData` получил:

- `resource_icon`;
- `resource_start`;
- `resource_max`.

`Battle` теперь хранит ресурсы билдов в общем словаре. `magical_charge` оставлен как совместимое свойство поверх ресурса `magical_charge`.

`AbilityData` получил `resource_cost`, поэтому новые способности могут расходовать уникальный ресурс без отдельной ветки в `battle.gd`.

## Универсальные эффекты

В `CardEffectProcessor` добавлены:

- `apply_status`;
- `trigger_status`;
- `damage_per_status_stack`;
- `extend_status`;
- `gain_build_resource`;
- `gain_resource_per_statused_enemy`.

`on_fire` теперь использует ту же базовую механику статусов, что и новый `poison`.

### Формат `apply_status`

Пример:

```gdscript
{
	"id": "apply_status",
	"status": "poison",
	"duration": 3,
	"stacks": 2,
	"damage_per_stack": 1,
	"damage_type": 0,
	"max_stacks": 10
}
```

Урон статуса происходит в начале хода заражённого врага. Duration уменьшается после его действия.

## Пакеты карт билдов

`CardData` получил `build_id`.

После выбора заражения `Battle`:

1. удаляет карты чужих билдов из руки, колоды и сброса;
2. добавляет отсутствующие `starting_cards` выбранного билда;
3. добирает руку обратно до 5 карт.

Это позволяет хранить несколько карт заражений в стартовой системе и реально менять игровой пакет после выбора формы.

Конструктор автоматически записывает `build_id` новым картам и infection-картам.

## Пассивки Доктора

- **Токсикология** — +5% исходящего урона за уровень, максимум 3; влияет и на Яд в момент его наложения.
- **Герметичная маска** — 4% общего сопротивления за уровень, максимум 3.

Обе автоматически отображаются и прокачиваются в журнале через существующую систему `PassiveData`.

## Дополнительное исправление

Временный бонус максимального HP билда больше не обрезается сразу значением постоянного `GameState.player_max_hp`. При выходе из боя HP снова ограничивается постоянным максимумом.

## Установка

Распаковать архив в корень проекта рядом с `project.godot`, заменив файлы.

После запуска в Output должно быть:

```text
Build Editor 0.37.0 loaded
```

## Что проверить в Godot

1. Открыть «Билды» — должны отображаться Magical Girl и Чумной Доктор.
2. В бою выбрать карту заражения Доктора.
3. Убедиться, что магические карты исчезли и в колоду добавился пакет Доктора.
4. Наложить Яд и завершить ход — урон должен пройти перед действием врага.
5. Набрать 3 Вирулентности и нажать третью способность — Яд должен сработать сразу, ход игрока не должен завершиться.
6. Открыть журнал → Doctor — должны появиться две пассивки с кнопками улучшения.

## Конструктор билдов

Во вкладке **«Баланс»** теперь можно без Inspector настроить уникальный ресурс билда:

- ID;
- отображаемое имя;
- стартовое значение;
- максимум;
- иконку.

Расчёт силы теперь учитывает ожидаемый DoT от `apply_status`, payoff `damage_per_status_stack`, принудительный `trigger_status` и стоимость способности в уникальном ресурсе. Поэтому DoT-билды больше не оцениваются как почти чистая «утилити».

## Отображение статусов врага

Существующий Intent теперь дописывает активные основные статусы, например:

```text
Атака (Физ.): 8
Яд x4 | Горение
```

Это временное компактное отображение до отдельного UI-контейнера иконок статусов у врагов.

## Автоматическое подключение новых билдов

`GameState` больше не содержит жёсткий список карт заражений. При `reset_run()` он сканирует `res://src/data/builds/definitions`, читает `activation_card_id` и добавляет найденные infection-карты автоматически.

Практически это означает: создать билд в конструкторе → создать ему «Карту заражения» → новый билд уже доступен в стартовом выборе без правки `game_state.gd`.


## v0.37.1 — исправления загрузки билдов

- infection-карты больше не имеют жёсткой ссылки на `ContaminationData`; используется стабильный `build_id`;
- `con_magical_girl` и `con_doctor` всегда добавляются в стартовую колоду напрямую;
- `Battle` разрешает билд по `build_id`, поэтому временно отсутствующая текстура не убирает карту заражения;
- журнал нормализует legacy ID (`con_*/inf_*`) и показывает путь проблемного `.tres`, если ресурс действительно не загрузился;
- исправлены несуществующие пути `spell_atk/def/utl_*.png`; utility-панель использует реальные `spell_button_<build>_a/b/c.png`;
- все динамические fallback-текстуры проверяются через `ResourceLoader.exists()` до `load()`, поэтому Output больше не должен заполняться ошибками отсутствующих PNG.
